## 1. Executive summary

This project segments the retailer's customer base using a classic
**RFM (Recency, Frequency, Monetary)** framework reinforced by an
unsupervised **k-means** cross-check. It converts the customer-transaction
dataset into **eight named business segments** (Champions, Loyal Customers,
At Risk – High Value, At Risk, New Customers, Hibernating, Lost,
Needs Attention) with a profile table quantifying size, revenue share and
behavioural averages. Marketing can then target campaigns and inventory
decisions per segment instead of treating all customers identically.

The pipeline is **fully reproducible**: synthetic sample data is generated by a
committed script, all analysis is R, and every run produces the same outputs.

## 2. Business context & objectives

The retailer operates through boutiques, a flagship store and e-commerce.
Historically, promotions and CRM communications were uniform. Management wants
to understand:

1. **Where value concentrates** — what share of revenue comes from which
   customer groups.
2. **Which customers to defend** — high-value customers whose purchasing is
   declining or stopping.
3. **Which customers to grow** — promising recent customers with low frequency.

**Success metrics**

- A segment profile table accepted by the retail manager (sign-off).
- At least one targeted campaign concept per segment proposed in the handover.
- Methodology documented so the analysis can be re-run quarterly.

## 3. Scope & non-goals

**In scope**

- Transaction- and customer-level data preparation and quality reporting.
- RFM scoring and rule-based segmentation; k-means cross-check.
- Segment profiles, charts, methodology spec, Jira/Confluence artefacts.

**Out of scope**

- Predictive modelling (churn scores, LTV forecasts) — future iteration.
- Campaign execution or ROI measurement — owned by marketing.
- Real production data — the committed data is synthetic and clearly labelled.

### 4.3 Known data-quality issues (and how the pipeline handles them)

| Issue | Handling |
|---|---|
| Duplicated transaction IDs | Keep first occurrence, count removed |
| Refunds / negative lines | Excluded from value metrics |
| Blank channel | Normalised to `Unknown` |
| Orphan transactions (no master row) | Flagged and excluded from RFM |
| Customers without any order | Kept in master, RFM left missing (dormant) |

## 5. Methodology

### 5.1 Step 1 — Data preparation (`analysis/01-data-preparation.R`)

1. Import both CSVs with `readr`.
2. Deduplicate on `transaction_id`; drop refunds; parse dates.
3. Normalise channel; flag orphan transactions.
4. Aggregate per customer:
   - **Recency** = days between reference date and last order,
   - **Frequency** = number of valid orders,
   - **Monetary** = total revenue (EUR),
   - *plus* average order value.
5. Join onto the master so dormant customers stay visible.
6. Output: `analysis_output/customer_rfm.csv` + quality counters in the console.

**Reference date:** `2026-09-01`, fixed so re-runs do not drift (see Decisions log).

### 5.2 Step 2 — RFM scoring & segmentation (`analysis/02-rfm-segmentation.R`)

1. Active customers only (non-missing Recency).
2. **Scores:** each dimension split into quintiles with `ntile`; 5 = best
   (most recent / most frequent / highest spend); composite 3–15.
3. **Segments:** rule-based assignment, evaluated in order:

| Rule | Segment |
|---|---|
| R=5 and F≥4 and M≥4 | Champions |
| R≥4 and F≥3 and M≥3 | Loyal Customers |
| R=5 and F≤2 | New Customers |
| R≤2 and M≥4 | At Risk – High Value |
| R≤2 and M≥2 | At Risk |
| R=1 and F≤2 and M≤2 | Lost |
| R≤2 and F≤2 and M≤2 | Hibernating |
| otherwise | Needs Attention |

4. **Cross-check:** k-means (k = 4) on log-transformed, scaled RFM;
   cross-tabulation segment × cluster printed.
5. Outputs: `analysis_output/segment_profiles.csv` + two base-R bar charts
   (customer share, revenue share by segment).

### 5.3 Interpretation guide

- **Champions / Loyal** → defend: VIP events, early access, dedicated service.
- **At Risk – High Value** → reactivate: win-back offers, boutique appointment.
- **New Customers** → grow: onboarding flow, second-purchase incentive.
- **Hibernating / Lost** → low-cost reactivation or let go.
- **Needs Attention** → large middle: uplift tests to find triggers.

## 8. Risks & mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Quintile boundaries unstable on small samples | Medium | Medium | Report counts per score; re-check quarterly |
| Rules misclassify borderline customers | Medium | Medium | k-means cross-check; manual sample review |
| Recency drifts over time | High | Medium | Fixed reference date + re-run cadence |
| Personal data governance | Medium | High | Synthetic data only; privacy note (US-12) |

## 9. Decisions log

| Date | Decision | Rationale |
|---|---|---|
| 2026-08-31 | Reference date fixed at `2026-09-01` | Reproducibility; avoids Recency changing between runs |
| 2026-09-01 | Use quintiles (`ntile`) for scores | Robust to skewed distributions; standard practice |
| 2026-09-03 | k = 4 for k-means | Balance between interpretability and granularity; reviewed vs 3/5 |
| 2026-09-04 | Refunds excluded, not offset | Keeps value metrics clean and auditable |
| 2026-09-05 | Orphan transactions excluded | No master attributes to profile them |
| 2026-09-08 | Charts in base R | Zero extra dependencies; easy for anyone to re-run |

## 10. Glossary

| Term | Definition |
|---|---|
| RFM | Recency, Frequency, Monetary — three behavioural dimensions used for segmentation |
| Recency | Days since the customer's last order |
| Frequency | Number of orders in the observation window |
| Monetary | Total revenue generated by the customer in the window |
| Quintile | One of five equal-size groups from a ranked distribution |
| k-means | Unsupervised clustering algorithm partitioning data into k groups |
| Orphan transaction | Transaction whose customer is absent from the master table |
| Dormant customer | Master customer with no valid order in the window |
