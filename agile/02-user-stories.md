# User Stories — Golden Customer Segmentation

Detailed versions of the sprint stories with **acceptance criteria** written in
Given / When / Then format. IDs match the [product backlog](01-product-backlog.md).

---

## US-04 · Customer-level RFM table

**As a** data analyst
**I want** a customer-level table with Recency, Frequency and Monetary
**so that** I can score and segment customers consistently.

**Acceptance criteria**

- GIVEN the cleaned transaction table, WHEN I aggregate by `customer_id`,
  THEN I obtain one row per customer with:
  - `recency_days` = days between the analysis reference date and the last order,
  - `frequency` = number of valid orders,
  - `monetary` = total revenue in EUR.
- GIVEN a customer with no valid order, WHEN the table is built, THEN the row is
  kept (from the master file) with missing RFM values, so dormant accounts remain visible.
- GIVEN the output CSV, WHEN opened, THEN columns are exactly
  `customer_id, recency_days, frequency, monetary, avg_order_value`.

## US-06 · Business segment assignment

**As a** marketing analyst
**I want** each active customer assigned to a named business segment
**so that** we can target campaigns differently per segment.

**Acceptance criteria**

- GIVEN the RFM scores (1–5 per dimension), WHEN the rules are applied in order,
  THEN every customer receives exactly one segment among:
  Champions, Loyal Customers, New Customers, At Risk – High Value, At Risk,
  Hibernating, Lost, Needs Attention.
- GIVEN a customer with R=5, F≥4, M≥4, WHEN the rules run, THEN the segment is `Champions`.
- GIVEN a customer with R≤2 and M≥4, WHEN the rules run, THEN the segment is
  `At Risk – High Value` (not plain `At Risk`).
- GIVEN any customer, WHEN the rules run, THEN no segment value is `NA`.

## US-07 · k-means cross-check

**As a** data scientist
**I want** a k-means clustering (k = 4) as a complementary view
**so that** we can validate that rule-based segments match data-driven groups.

**Acceptance criteria**

- GIVEN the RFM table, WHEN clustering runs, THEN features are log-transformed
  and scaled, and a fixed random seed makes results reproducible.
- GIVEN the cluster labels, THEN a cross-tabulation (segment × cluster) is printed,
  so the analyst can judge agreement.
- GIVEN the run, THEN no customer is left without a cluster label.

## US-08 · Segment profile table

**As a** retail manager
**I want** a segment profile with size, revenue share and average order value
**so that** I can see where customer value concentrates.

**Acceptance criteria**

- GIVEN the segmented table, WHEN I summarise by segment, THEN I get:
  number of customers, % of customers, % of revenue, average recency,
  average frequency, average monetary and average order value.
- GIVEN the profile, THEN segments are sorted by size (descending).
- GIVEN the output CSV, THEN it is saved as `analysis_output/segment_profiles.csv`.

## US-10 · Methodology spec (Confluence-style)

**As a** project lead
**I want** the project methodology written as a structured spec document
**so that** the project is shareable with stakeholders and reusable next time.

**Acceptance criteria**

- GIVEN the spec, THEN it contains: business context, objectives, scope,
  data dictionary, methodology, acceptance criteria, timeline, risks, decisions log.
- GIVEN the spec, THEN it is written in plain language a non-technical stakeholder can follow.
- GIVEN the spec, THEN every decision (e.g. RFM reference date, k = 4) is
  recorded with its rationale.

## US-11 · Reproducible end-to-end pipeline

**As a** developer
**I want** the pipeline to run end-to-end deterministically
**so that** results can be regenerated and audited at any time.

**Acceptance criteria**

- GIVEN the repository, WHEN I run
  `source("analysis/01-data-preparation.R")` then
  `source("analysis/02-rfm-segmentation.R")`,
  THEN the outputs are produced without errors.
- GIVEN the same data and a fixed random seed, WHEN I run twice,
  THEN results are identical.
- GIVEN sample data, THEN it is generated by a committed, deterministic script
  (`python data/00_generate_sample_data.py`).
